Step-by-step flow
1
User

User opens a GitHub Issue

A developer writes an issue like "Fix the login bug — users can't reset password" and tags @claude in the body or comment. This is the trigger.

2
GitHub

GitHub fires an issues webhook event

GitHub detects the issue was created/commented on and emits an event. This event is picked up by the GitHub Actions workflow configured in the repo (e.g. .github/workflows/claude.yml).

3
Runner

GitHub spins up a fresh Actions Runner VM

GitHub provisions a temporary Ubuntu virtual machine on GitHub's cloud infrastructure. This is an ephemeral, isolated environment — it exists only for this job run, then gets destroyed.

4
Runner

Runner checks out the repository

The workflow runs actions/checkout, cloning the full repo into the runner's filesystem. Claude Code will use these files as its working directory.

5
Claude Code

Claude Code is invoked inside the Runner

The workflow calls the anthropics/claude-code-action GitHub Action, passing it the issue title and body as the prompt. Claude Code starts running inside the Runner VM using your ANTHROPIC_API_KEY secret.

6
Claude Code

Claude reads the codebase & reasons about a fix

Claude Code uses its tools — ReadFile, Glob, Grep — to navigate the repo, understand the code, and plan a fix based on the issue description.

7
Claude Code

Claude makes code changes

Claude edits files directly on the Runner's filesystem using its WriteFile / Edit tools — the same repo it checked out in step 4.

8
Runner

Tests run inside the Runner VM

Claude runs the test suite (e.g. npm test or pytest) via Bash — still inside the same Runner VM. The app is not deployed anywhere; it runs locally inside this temporary VM.

9
GitHub

Claude opens a Pull Request

Claude commits its changes and uses the GitHub API (via the provided GITHUB_TOKEN) to push a branch and open a PR — referencing the original issue. The Runner VM is then destroyed.

10
User

Developer reviews & merges the PR

The PR appears in GitHub for a human to review, request changes, or approve. Claude may also comment on the issue to summarise what it did.

Your questions answered
Q1 Where does the app run when @claude tests it?
The app runs inside the GitHub Actions Runner — a temporary Ubuntu VM hosted on GitHub's cloud servers.
✗ Not your local machine
✗ Not Anthropic's servers
✓ GitHub's ephemeral cloud VM
Claude installs dependencies and runs the tests (npm test, pytest, etc.) directly in that VM's shell. The VM is destroyed after the job completes.
Q2 How does the GitHub Action run when a user creates an issue?
The workflow file (.github/workflows/claude.yml) is configured to trigger on the issues event:

on: issues: types: [opened]

When a new issue is created, GitHub fires this event → the Actions workflow starts → the Runner VM spins up → Claude Code is invoked with the issue text as its prompt → it works autonomously and opens a PR.

Required secrets in the repo:
• ANTHROPIC_API_KEY — authenticates Claude
• GITHUB_TOKEN — lets Claude push branches & open PRs (provided automatically by GitHub)
Key insight
Claude Code in GitHub Actions is just Claude Code running in a CI environment — the same tool you use locally, but triggered by GitHub events and running in GitHub's cloud instead of your terminal.
